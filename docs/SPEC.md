# Cyno milestone 1 - spec

## Scope

Milestone 1 is the one the README names: take a latitude, longitude and date, and return a ranked list of observable objects with the reasoning shown.
It ships as two parts in one pnpm workspace: `packages/engine` (pure TypeScript, no DOM, works offline) and `apps/web` (a React app that calls the engine in the browser).
There are no API keys, no paid services, no server and no model calls at runtime.
The only network call is an optional cloud cover forecast from Open-Meteo, made by the web app; everything else works offline.
The conversational agent, notifications, news digest, AR and the Android app from `GPTPlan.md` and `GeminiPlan.md` are out of scope.
From `GeminiPlan.md` this milestone keeps the night-first look, the Red-Light Mode toggle, glass panels, and the Go/No-Go verdict.

## Data flow

1. The web app collects latitude, longitude, date, sky quality and equipment (geolocation button, place presets, or typed coordinates).
2. It asks Open-Meteo for hourly `cloud_cover` for that place and those two days; on any failure it carries on with cloud cover unknown.
3. It calls `planNight(input)` from the engine, synchronously, in the browser.
4. It renders the verdict, the ranked list with each object's reasoning, the sky chart, and the night timeline from the returned `NightPlan`.

## Engine interface (`packages/engine/src/index.ts`)

`planNight(input: PlanInput): NightPlan` is pure and deterministic, and throws `PlanInputError` (with `errors: InputError[]`) on invalid input.
`parsePlanInput(raw: unknown): ParseResult` validates untrusted input without throwing.
`resolveTimeZone(lat, lon): string` returns the IANA zone for a point, offline, using `@photostructure/tz-lookup`.
`catalog` exports the star and deep-sky list from `src/data/catalog.json`.
All types live in `src/types.ts`; that file is the contract and changes only with the lead's review.

## Astronomy

Positions, rise and set times, twilight and Moon phase come from `astronomy-engine` (MIT, validated by its author against JPL Horizons and NOVAS); nothing is hand-rolled.
Planets and the Moon use `Equator(body, time, observer, ofdate=true, aberration=true)` then `Horizon(..., refraction=null)`, so altitudes are geometric and topocentric.
Catalog objects (J2000 RA/Dec) are rotated to the horizon frame with `Rotation_EQJ_HOR(time, observer)`, one matrix per sample.
Sunrise and sunset use the standard -0.833 degree definition through `SearchRiseSet`; twilight edges use `SearchAltitude` at -6, -12 and -18 degrees.
Planet magnitudes come from `Illumination(body, time).mag`; Moon illumination and phase angle come from `Illumination(Body.Moon, time)`.
The objects are the Moon, the seven planets from Mercury to Neptune, the 85 IAU-named stars brighter than V = 2.5, and 109 Messier objects.
The catalog is generated by `scripts/build-catalog.py` from IAU-CSN, OpenNGC, the Harris globular cluster catalog and, for M35 alone, NGC 2000.0 as served by NASA HEASARC; M102 is left out because it has no agreed identification (OpenNGC files it under M101), which leaves 109 of the 110.

## The night

The night window runs from local noon on `date` to local noon the next day, in the resolved time zone.
The engine samples it every `stepMinutes` (default 10).
Darkness at each sample follows the Sun's altitude, with the thresholds in `types.ts`.
The dark window is the longest continuous run at the darkest level reached tonight (night, else astronomical, else nautical, else civil twilight).
`condition` names the kind of night: normal, no-astronomical-darkness, no-nautical-darkness, white-night, polar-day or polar-night.

## Limiting magnitude (a documented heuristic, not a measurement)

Zenith sky brightness by preset, in V mag per square arcsecond: city 18.0, suburban 19.5, rural 21.0, dark 21.7.
Twilight adds a sky of `21.7 - 0.6 * (h + 18)` mag per square arcsecond for Sun altitude h between -18 and 0 degrees, and nothing below -18.
Moonlight at the target's position follows Krisciunas and Schaefer (1991, PASP 103, 1033), with extinction coefficient k = 0.25.
Sky, twilight and moonlight are added as fluxes, not magnitudes.
Naked-eye limiting magnitude from total sky brightness B is `7.93 - 5 * log10(10^(4.316 - B / 5) + 1)`, an empirical approximation.
Equipment adds a fixed gain: eye 0, binoculars 3.0, telescope 5.5 magnitudes.
An object's effective magnitude is its catalog magnitude plus extinction `k * (X - 1)`, with airmass X from Krisciunas and Schaefer's formula, plus a diffuse-object penalty by kind: galaxy 1.5, nebula 1.0, planetary nebula 0.5, globular cluster 0.5, open cluster 0.5, others 0.
The margin is limiting magnitude minus effective magnitude.

## Visibility

An object is visible at a sample when the Sun is below -0.833 degrees, the object is at least 10 degrees up, its margin is at least 0, and cloud cover is below 80 percent or unknown.
An object that is never visible tonight goes to `hidden` with the first reason that applies: never above 10 degrees in the dark, too faint for this sky and equipment, or clouded out.
The best moment is the visible sample with the largest margin; ties go to the higher altitude, then the earlier time.

## Ranking rule and what "reasoning shown" means

Each visible object gets a score from 0 to 100, built from six factors whose points add up to the score.
Altitude: `30 * clamp((alt - 10) / 50, 0, 1)` at the best moment, so 60 degrees or higher earns the full 30.
Brightness: `35 * clamp(marginWithoutMoon / 5, 0, 1)`, where marginWithoutMoon is the margin with the Moon's light removed.
Moon: `35 * clamp(margin / 5, 0, 1)` minus the brightness points, so it is zero or negative and shows exactly what moonlight costs; it is zero for the Moon itself.
Duration: `20 * clamp(hoursVisible / 4, 0, 1)`.
Darkness at the best moment: night 15, astronomical twilight 10, nautical twilight 5, civil twilight 2.
Clouds: minus the sum of the other five times `cloudPercent / 100` at the best moment; zero, labelled "no forecast", when cloud cover is unknown.
Objects are sorted by score, then by margin, then by name.
"Reasoning shown" means every object carries its six factors, each with a label, the measured value in plain words, the points, and one sentence, plus a one-line summary with the best time and direction.
The UI shows that breakdown for any object the user selects, and the hidden list says why each missing object is missing.

## Go/No-Go verdict

Darkness points: `40 * clamp(darkWindowHours / 4, 0, 1)`, using only a dark window at night or astronomical-twilight level.
Moon points: `30 * (1 - illumination * moonUpFraction)`, where moonUpFraction is the share of the dark window between the plan's own moonrise and moonset.
Cloud points: `30 * (1 - meanCloud / 100)`, where meanCloud is the time-weighted mean over the parts of the dark window the forecast covers.
When the forecast covers less than half of the dark window, cloud cover counts as unknown: these 30 points are left out and the other 70 are scaled to 100.
Go at 65 or more, marginal from 35, no-go below 35.
The verdict is no-go with score 0 when there is no dark window (polar day) or when the darkest level is civil twilight (white night), whatever the Moon and clouds; the dark window is still reported for the timeline.
Reasons are plain sentences, for example "Dark from 18:15 to 05:20 (11.1 hours)."

## Input handling

Latitude outside -90..90, longitude outside -180..180, non-numbers, a malformed or impossible date, an unknown time zone, equipment or sky, a step outside 1..60, an elevation outside -500..10000 metres (astronomy-engine's rise and set refraction fails above about 43 km), and cloud values outside 0..100 are input errors with a field and a message.
Polar day, polar night and nights without full darkness are normal results with their `condition`, never errors.

## Web app

React 19, Vite, TypeScript and Tailwind CSS v4, with components adapted from 21st.dev, React Bits, Magic UI and Aceternity UI.
The sky chart is an SVG azimuthal projection (zenith in the centre, horizon at the edge, north up, east to the left as seen looking up), showing the ranked objects and the bright stars at the selected time, with a time scrubber shared with the timeline.
The night timeline shows the Sun's darkness bands from sunset to sunrise, the Moon's altitude, the cloud forecast when known, and the selected object's altitude.
Red-Light Mode turns the whole interface deep red to protect night vision, and the choice is remembered in the browser.
Times show in the location's time zone with its name.
The app states its limits plainly: positions are computed, visibility is an estimate.

## Test plan

Engine tests compare against published reference data stored unmodified in `packages/engine/test/fixtures/raw/`, retrieved on 2026-11-17.
USNO Astronomical Applications API, Long Beach (33.77 N, 118.19 W), 2026-11-17, UTC-8: sunrise 06:27, sunset 16:48, civil twilight 06:00 and 17:15, moonrise 12:43, illumination 53 percent; times must match within 1 minute (2 for the Moon).
USNO, Tromso (69.65 N, 18.96 E), 2026-12-21: the Sun stays below the horizon, civil twilight 09:31 to 13:53 at UTC+1; 2026-06-21: the Sun stays above the twilight limit.
USNO 2026 Moon phases: all 50 primary phase times must match within 2 minutes.
JPL Horizons (DE441), Long Beach, 2026-11-18 05:00 UTC, airless apparent azimuth and elevation of the Sun, Moon, Venus, Mars, Jupiter and Saturn: must match within 0.1 degree.
JPL Horizons, Sun elevation each minute from 00:40 to 02:40 UTC on 2026-11-18: the engine's nautical and astronomical dusk must fall within 1 minute of where Horizons crosses -12 and -18 degrees.
Invariants (no published value used): Polaris's altitude is within 1 degree of the latitude; factor points sum to the score; the list is sorted; more moonlight never raises the limiting magnitude; better equipment never removes an object; every hidden object has a reason; invalid input yields field errors.
The web app has component tests for the reasoning panel and the empty and error states, and a Playwright smoke test that loads the built app, shows a ranked list, and saves screenshots at 1440 and 390 pixels wide.
`pnpm check` runs lint, type-check, tests and build, and must pass.
